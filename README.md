# 灵感回声

中文个人灵感资料库：记录零碎想法，补充来源，用 AI 整理，再用自己的话写一次，日后按关键词找回。

本项目的生产路线是中国腾讯云：上海 `ap-shanghai` CloudBase PostgreSQL、CloudBase 身份认证、CloudRun 云托管和平台内 AI。正式记录保存在云端，同一私人账号可在手机和电脑使用；浏览器仅保留按账号隔离的捕捉草稿。

**当前尚未完成生产交付，没有可交付的访问地址。** 腾讯云账号已注册并完成实名认证；CloudBase 环境尚未创建，真实数据库、私人账号、AI 调用、正式域名和手机完整流程仍待验收。构建、模拟测试或配置检查通过，都不代表线上产品已可用。状态和待办见 [部署配置清单](./部署配置清单.md)。

## 使用方式

1. 用私人邮箱和初始化生成的密码登录正式 HTTPS 地址。没有公开注册入口。
2. Apple Watch 可用已有记事或听写方式捕捉想法，再把文字、播客链接复制到网站；网站暂不自动读取手表或 Apple 备忘录。
3. 在“记录”页写想法并补充来源名称、链接、时间点和真实片段。“先保存”收到云端确认后才算正式保存；“保存并整理”会先保存，再请求 AI。
4. 在详情页写自己的理解并保存。搜索覆盖原始想法、来源、AI 整理和个人输出。
5. 另一设备登录同一账号即可查看云端资料。页面会定期、回到前台或恢复联网时刷新。同时编辑会提示版本冲突，需核对后再保存。
6. 导出完整 JSON 备份。大资料库会分成多个独立文件，全部下载；恢复时逐份确认。Markdown 仅用于阅读。

iPhone 可在 Safari 分享菜单选择“添加到主屏幕”。保存和同步需要联网；未保存的捕捉草稿只存在当前浏览器。演示资料必须明确标注“演示资料”。只有链接时仍要补充想法或来源正文，AI 才会整理。

## 腾讯云部署

选择上海 PostgreSQL 环境，不能用文档型数据库替代。Next.js 通过本项目 Dockerfile 部署到 CloudRun，保留 SSR 与服务端 API，容器监听 `0.0.0.0:3000`，使用 Node 24 和非 root 用户。官方流程见 [CloudBase Next.js 云托管指引](https://docs.cloudbase.net/recipes/deploy-nextjs-to-cloudbase-run)。

免费体验是否可领取、资源点、续期及功能限制以腾讯云账号购买页为准。官方说明免费体验需要兑换码、按月提供资源点、续期需手动操作；这不是不限时不限额的免费生产承诺，参考 [腾讯云免费体验说明](https://cloud.tencent.com/document/product/876/127357)。默认域名必须由实际部署结果返回；长期限制、自定义域名、证书和备案按 [官方域名指引](https://docs.cloudbase.net/run/deploy/networking/custom-domains) 确认，本项目不承诺免备案。

### 运行配置

| 变量 | 用途 |
| --- | --- |
| `CLOUD_PROVIDER=cloudbase` | 选择腾讯认证、数据库和 AI |
| `CLOUDBASE_ENV_ID` | 实际创建的 PostgreSQL 环境 ID |
| `CLOUDBASE_REGION=ap-shanghai` | 上海地域 |
| `CLOUDBASE_AI_MODEL` | 该环境实际开通并验证可用的模型名 |
| `CLOUDBASE_APIKEY` | 该环境的 api_key 类型密钥，供容器内调用 AI 模型 |
| `OWNER_USERNAME=echo-owner` | CloudBase 私人用户名 |
| `OWNER_EMAIL` | 真实私人邮箱和网站登录标识 |
| `APP_ORIGIN` | 最终正式 HTTPS 来源地址 |

所有变量仅服务器使用，不使用 `NEXT_PUBLIC_`。邮箱登录映射到指定 CloudBase 用户名，服务器通过真实用户信息接口核对用户名和 ID；数据库访问使用当前用户令牌，不使用管理员凭据。

**关于 `CLOUDBASE_APIKEY`**：云托管容器拿不到 `TENCENTCLOUD_*` 临时密钥，容器运行角色（`TCB_QCSRoleInRunLog`）也没有大模型调用权限，因此容器内直接调用 AI 会返回 401。`@cloudbase/node-sdk` 会自动读取 `CLOUDBASE_APIKEY` 并跳过凭据换取流程，这是当前可用的容器内 AI 授权方式（2026-09-22 实测确认）。该密钥只存在于服务器环境变量，不进入镜像、不进入浏览器。

初始化脚本会创建或确认 `echo-owner`，应用 `cloudbase/migrations/`，加入真实用户 ID 白名单并启用用户名密码登录。新密码写入本机 `.env.tencent-owner.local`，不打印、不上传、不放入命令参数。已有账号不会静默重置。

```sh
npm ci
node scripts/setup-tencent.mjs --check
node scripts/setup-tencent.mjs --apply
npm run check:deployment
npm run typecheck
npm test
npm run build
```

检查脚本不联网、不修改资源、不输出值，不能证明平台权限、额度或 AI 已可用。运行配置改变后要发布新版本。CloudRun 实际 URL 确认后再填 `APP_ORIGIN`。

## 数据与 AI

正式数据含想法、来源、AI 整理和个人理解。服务器确认写入后才返回成功；版本校验避免旧设备静默覆盖。AI 只在主动点击整理时读取当前记录，发送想法、来源片段及名称、链接、时间点等定位信息，不发送整个资料库，也不自动打开链接。没有正文时不会从链接编造内容。

腾讯模型通过文字指令生成 JSON，服务端再严格检查结构和来源归属；不声称平台提供强制 JSON Schema 保证。权限、额度、超时、格式或写入失败均不会显示成功。密码修改需当前密码及绑定邮箱或手机验证码；网站暂未提供“忘记密码”自助找回。

备份不含会话、密钥或未保存草稿。单次恢复上限 4 MiB，导出目标约 3.5 MiB/份，必须保存并恢复全部分卷。

### 每日打卡

账号与设置中的打卡牌使用独立的 `echo_checkins` 表。腾讯部署需应用 `cloudbase/migrations/20260921000200_daily_checkins.sql`；保留的 Supabase 部署使用对应 `202609210002_daily_checkins.sql`。既有初始化脚本会按顺序发现并应用新迁移，无需额外密钥。未部署此迁移时，API 会明确返回“云端打卡尚未初始化”，不会冒充保存成功。

每日按数据库的北京时间（Asia/Shanghai）划分，同一账号每天只保存一条，重复点击或另一台设备重试保留首次内容。跨午夜的旧页面提交会要求刷新日期。累计天数只统计已保存日期；连续天数在今日尚未打卡时延续到昨天，漏掉完整一天后归零。心情最多 24 字、金句最多 100 字。预览页的打卡仅为页面内演示，不写入云端；现有灵感集 JSON 备份不包含打卡记录。云端真实写入及跨设备流程仍需在正式部署后验收。

## 生产验收

只有实际正式地址完成以下流程，才可宣布交付：真实登录/退出/改密；两台设备保存、读取、编辑和冲突；真实 AI 整理并写入；JSON 分卷恢复；手机浏览器完成登录、保存、整理、详情、搜索和退出。未接通、失败或未确认的操作不得显示成功。现有本地模拟测试不代替公网验收。
