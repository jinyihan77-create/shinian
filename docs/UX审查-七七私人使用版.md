# 拾念 UX 审查：七七私人使用版

日期：2026-09-23  
结论：产品已经有鲜明的星河、票根和摘星记忆，但核心动作仍被隐喻、入口层级和不一致的交互遮住。优化目标不是继续加栏目，而是让记录、找回、推进和回看四件事不需要解释。

## 当前最影响顺手程度的卡点

### 1. 比喻比动作更醒目

“启程票、终点票、现在启程、继续做”需要先理解一套规则。票根可以继续作为视觉形式，但按钮直接写“开始并打开、打开记录、标记完成、重新列入待办”，状态只保留“待开始、进行中、已完成”。

### 2. 每日仪式藏得太深

摘星具有记忆点，却位于设置页并要求额外进入、选择和确认。规划上应在当天第一条记录保存后，直接在记录页露出“一键摘星”；星卡根据当天原话生成，调整成为可选步骤。

### 3. 语音只在部分入口成立

主记录支持语音，而找回念头只能打字，用户会在两套输入习惯间切换。搜索需要同样的语音入口，并在聆听时给出清晰、科技感但不刺眼的状态反馈。

### 4. 首页缺少持续变化

“此刻，想记下什么？”长期静止后会像表单标题。标题应轮换成贴近夜间私人场景的问题，进入输入后停止轮换，避免分散注意力。

### 5. 分类粒度超过真实使用频率

“散步、整理思路”等细标签要求用户在捕捉前先整理自己。高频筛选只保留“全部、待办、闪卡”，主题放进二级入口；搜索改成“想问过去的自己什么？”。

### 6. AI 的完成边界不清楚

用户连续口述时，停顿不等于说完。AI 不应在短暂停顿后自动总结。未来流程以“原文先保存、系统轻问、用户明确确认、再开始整理”为准，并保留原文和差异对照。

### 7. 个人感仍可更强

“七七”和数字 7 可以成为稳定签名：`Q7/07` 用在星卡编号、书脊和七日星轨；每周让过去的七七向现在提一个真实问题。它应克制出现，保持私人而不变成主题装饰。

## 本轮直接实施

- 记录标题改为滚动提问，输入时暂停。
- 主语音输入增加发光声波与明确聆听状态。
- 资料库命名统一为“回声屿”。
- 回声屿搜索增加语音入口，高频筛选收敛为三个。
- 票根删减正文，改用问题引导并明确每个动作的结果。
- 主要按钮增加粉色玻璃与边缘微光，轻按钮继续保持安静层级。

## 暂不实施

- 恋爱、白羊与水瓶内容。
- 相册、拾光簿和每日手账。
- AI 自动总结与批量润色。
- 摘星入口迁移和七日成长机制。

这些内容需要先确定真实数据、AI 触发边界与跨设备保存方式，再进入开发。
