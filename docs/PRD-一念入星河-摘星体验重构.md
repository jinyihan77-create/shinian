# 「一念入星河」摘星体验重构 PRD

版本：2026-09-23  
状态：待主线执行  
适用产品：拾念  
优先级：P0，替换现有摘星到矩形吊牌的完整流程

## 0. 决策说明

本 PRD 记录用户对摘星体验的最新决定，并覆盖旧文档中的冲突规则。

- 覆盖 `docs/PRD-2026-09-23-体验修复与原创设计恢复.md` 第 7 节中“吊牌保持圆角实体牌形，不改成星形”的要求。
- 覆盖 `docs/PRD-拾念私人星卡与拾光手账.md` 第 4 节中“保留原有矩形主吊牌”的要求。
- 保留现有私人账号、北京时间每日一条、真实保存、累计天数和跨设备读取能力。
- 恋爱、星座运势、照片手账仍按原规划处理，不在本次摘星重构中扩展实现。

最新产品决定：用户摘下的那一颗星，必须作为同一个视觉对象继续展开，最终成为可阅读、可回看的七芒星形卡片。流程中不得再突然替换成长方形吊牌。

## 1. 背景与问题

现有流程由两个彼此割裂的体验拼接而成：

1. 用户先在悬挂星幕中拖动或点击一颗星。
2. 星星消失，界面切换到一张使用独立模型、纹理和物理效果的矩形吊牌。
3. 页面同时承担星空动画、卡面图片生成、三维模型加载、物理计算、接口读取和自动保存。

真实使用中的问题：

- **物体不连续**：动作叫“摘星”，结果却是一张矩形证件牌，用户无法理解两者的关系。
- **等待感强**：选星后会经历生成图片、加载模型、等待三维场景就绪和自动保存，操作像卡住。
- **信息层级混乱**：引导语、牌面、编辑区、翻面和保存状态互相争夺空间。
- **重复进入疲劳**：每次打开都重新选择、加载和展示，仪式感很快变成负担。
- **视觉不稳定**：当前主题随机生成，同一天重新进入也会变化，削弱“这是今天那颗星”的记忆。
- **卡面文字不清晰**：文字被绘制进纹理后再贴到三维模型上，小字和移动端容易模糊。
- **保存逻辑不透明**：视觉结果与云端确认不是同一时刻，用户不容易判断是否真的保存。

## 2. 产品目标

把摘星从一个设置页里的额外打卡功能，重构为记录完成后的每日私人仪式：一条念头变成一点光，用户穿过自己的星河，摘下其中一颗，星星在手中展开成当天的七芒星笺。

必须达到以下结果：

1. 从进入到看到今日星笺，完整路径逻辑连续，没有“星星突然变卡牌”的跳变。
2. 首次体验有沉浸感，重复进入足够快，不强迫用户每天看完整动画。
3. 摘星本身即代表收下今天，不再要求第二次确认。
4. 星笺内容优先来自当天真实记录，不编造用户没有表达过的情绪或事件。
5. 同一天在同一账号的不同设备上看到同一片星海、同一种材质和同一张星笺。
6. 桌面端、手机端、低性能设备和减少动态效果模式都能顺畅完成核心流程。
7. 保存未被服务器确认时必须明确显示“等待同步”或失败，不能假装成功。

## 3. 非目标

本轮不做以下内容：

- 不接入新的星座运势或恋爱内容生成。
- 不把摘星改造成游戏，不加入积分、排行、连续打卡惩罚或抽卡稀有度。
- 不要求真实天文模拟。
- 不增加背景音乐自动播放。
- 不把每日星笺塞入长篇日记或大量信息。
- 不继续维护原三维矩形吊牌作为主体验。

## 4. 核心体验原则

### 4.1 同一颗星原则

从星海中的候选星、被摘下的星，到最终星笺，颜色、光环、纹理和位置运动必须连续。允许星星放大、展开、翻转和改变内部排版，不允许淡出后换成另一个不相干的物体。

### 4.2 一天一次完整仪式

- 当天第一次进入且尚未摘星：可以播放完整旅程。
- 当天已经摘星：直接打开今日星笺，不再重复选择。
- 当天未摘星但用户已经主动跳过旅程：再次进入直接到星海。
- 用户快速滚动、点击“直接到星海”或开启减少动态效果时，旅程必须立即缩短。

### 4.3 一次动作完成

摘下一颗星即触发今日记录的创建与保存。心情和文字修改属于可选的“调整星笺”，不能成为完成流程的必经步骤。

### 4.4 仪式不制造压力

不使用“断签”“还差一天”“连续记录归零”等焦虑表达。主要反馈是“今天留下了一颗星”和累计收藏；七日星轨用于回看，不用于惩罚。

### 4.5 文字始终清晰

星笺文字使用真实 DOM 或清晰的矢量文字层，不烘焙进低分辨率图片，不随三维透视持续倾斜。发光只用于轮廓、星芒和图标，不能糊化正文。

## 5. 入口与触发时机

### 5.1 主入口

摘星入口从设置页的日常操作区移到记录页，出现在当天第一条有效记录真实保存成功之后。

入口表现为页面边缘的一点缓慢呼吸的微光和一句克制提示：

> 今晚的星海，已经亮起。

用户可以继续记录，不弹窗、不遮挡输入、不显示红点催促。点击微光后进入星河旅程。

### 5.2 次入口

- 设置页只保留“今日星笺 / 过往星轨”的管理入口，不再承担每日摘星主动作。
- 当天没有记录时，用户仍可主动进入星海，但系统不得生成虚假心情或虚假金句，应提供“留一颗无字星”或“先说一句”的选择。
- 当天已有云端星笺时，任何入口都直接进入“回看今天”状态。

### 5.3 打扰控制

- 每天只自动露出一次邀请。
- 用户关闭邀请后，当天不再次主动浮出，但入口仍可从记录页找到。
- 不使用系统通知或声音提醒。

## 6. 完整用户流程

### 6.1 首次进入：桌面端完整旅程

1. **念头亮起**  
   用户保存当天第一条记录后，最新一句原话末尾凝成一个光点。光点停在记录区边缘，等待用户主动进入。

2. **离开文字**  
   用户点击入口，当前文字保持可见，镜头开始跟随光点向前。无需等待新的大资源加载完成才响应。

3. **穿过回声**  
   通过 2 至 3 次滚轮推进，光点经过由过往记录形成的抽象星尘和少量关键词。整个段落控制在约 3 至 5 秒，不能成为长滚动网页。

4. **抵达今夜星海**  
   镜头停下，远景收束为三颗可选星。默认高亮一颗“今晚的星”，另外两颗作为材质偏好，不制造选择焦虑。

5. **摘下一颗星**  
   用户可以点击、按 Enter，或向自己方向轻拖。手势达到阈值后有明确反馈；未达到阈值则自然回位，不误选。

6. **星星展开**  
   被选中的星保持原材质和光环，移动到视觉中心，七个星芒舒展，中央形成可阅读区域。其他星和背景降低亮度，不突然切屏。

7. **生成七芒星笺**  
   正面显示当天一句回响；轻扫、点击或键盘操作可查看背面累计天数和七日星轨。摘星动作同时发起保存。

8. **保存反馈**  
   云端确认后显示低干扰反馈“已留在今天”。如果仍在同步，显示“已留在本机 · 等待同步”；失败则保留星笺和文字，并提供明确重试。

### 6.2 重复进入

- 当天已摘星：直接展示今日星笺，入口文案改为“回看今天的星”。
- 当天只看过旅程但没有摘星：直接抵达候选星区域。
- 第二天：生成新的星海气候和候选星材质，再允许完整旅程。

### 6.3 手机端

手机端保留“念头化为光点 → 抵达星海 → 摘星 → 展开”的叙事，但不使用滚轮式长镜头：

1. 点击入口后以一次短推镜进入星海，时长控制在 1.2 至 1.8 秒。
2. 星海只显示三颗可触摸候选星，触摸目标不小于 48px。
3. 支持轻点选择；拖动只是增强体验，不能成为唯一操作。
4. 星笺中央文字区按屏宽布局，七个星芒可以延伸到安全区，但不得导致横向滚动。

## 7. 桌面端“一镜到底”设计

### 7.1 镜头结构

整段旅程只允许三个可感知阶段：

| 阶段 | 视觉 | 用户动作 | 时长上限 |
| --- | --- | --- | --- |
| 离开文字 | 记录文字变暗，光点向前 | 第一次滚动 | 1.2 秒 |
| 穿过回声 | 星尘、轨迹、模糊旧关键词 | 第二次滚动 | 1.8 秒 |
| 抵达星海 | 三颗候选星从远到近稳定下来 | 第三次滚动或自动吸附 | 1.2 秒 |

滚动只推进阶段，不按原始滚轮距离无限移动。触控板连续事件需合并，防止一次手势直接越过所有内容。到达星海后立即释放滚轮控制，页面不再被劫持。

### 7.2 导航与跳过

- 画面边缘使用 7 个极小光点作为个人签名和旅程进度，不显示传统进度条。
- 始终提供低干扰“直接到星海”。
- `Esc` 可退出并回到原记录位置。
- `Space`、`ArrowDown` 和 PageDown 可推进；Tab 可正常到达候选星和关闭按钮。
- 快速滚动意图明确时直接抵达下一稳定阶段，不播放拖沓的中间补间。

### 7.3 过往内容的呈现

- 默认只显示抽象光轨、日期和极短关键词，不展示完整私人原文。
- 在“隐私模式”或共享屏幕时只显示星尘，不显示关键词。
- 没有历史记录时使用稀疏星海，不伪造旧回忆。

## 8. 候选星与选择设计

### 8.1 数量

每次只提供三颗候选星：一颗推荐星、两颗可选星。现有七颗同时悬挂会增加视觉噪音和选择时间，不作为主流程保留。

### 8.2 选择含义

三颗星只代表材质偏好，不代表运气、稀有度或结果好坏。内容在选择前已经由当天真实记录准备好，用户不用猜“选错会不会得到不同文案”。

### 8.3 交互反馈

- 悬停或聚焦：星芒轻微变亮，材质表面出现一次低幅流光。
- 拖动：附近星尘产生局部响应，背景不整体晃动。
- 达到摘取阈值：轮廓收紧并出现一次短促星芒，不依赖文案才能理解。
- 松手后：选中星进入展开动画，其他星退到远景。
- 摘下后的 5 秒内允许“放回星海”，用于撤销误选；如果保存已经发出，撤销应取消或删除当天新建记录，不能只改视觉。

## 9. 七芒星笺设计

### 9.1 为什么是七芒星

七芒星与用户“七七”和产品中的 `Q7` 个人签名建立联系，同时让结果仍然明确是一颗星。七芒结构只作为私人识别，不在全站重复滥用。

### 9.2 形态

- 外轮廓是清晰的七芒星，不是把长方形贴进星星背景。
- 中央使用较宽的半透明七边形阅读区，七个星芒负责轮廓、材质和光泽。
- 星芒边缘带克制的星芒微光和细亮描边，不使用大面积紫色雾斑。
- 卡片可以有轻微视差和呼吸光，阅读时正面保持接近平视，避免文字跟着三维牌持续摇晃。

### 9.3 正面信息

只保留四层：

1. `Q7` 与日期。
2. 一个不超过 12 个汉字的状态词；有真实记录才生成。
3. 当天一句回响，建议不超过 32 个汉字，最多 2 至 3 行。
4. 极小的“来自今天 X 条记录”来源提示。

不在正面显示操作说明、连续天数、长段落或大面积品牌字。

### 9.4 背面信息

- 累计留下的星星数量。
- 最近七天的七点星轨；没有记录的日期保持暗点，不显示断签警告。
- 今天在星轨中的位置。
- “查看来源”入口，返回当天原始记录。

### 9.5 编辑

- 默认不出现输入框。
- “调整星笺”放在次级菜单中，展开后允许修改状态词和一句回响。
- 用户修改后自动保存，明确显示保存中、已保存或未同步。
- 用户手动修改过的内容不能被后续自动整理覆盖。

## 10. 每日变化系统

### 10.1 稳定随机

星海不能每次刷新都随机变化。视觉种子由“账号标识 + 北京日期 + 体验版本”稳定生成：

- 同一账号同一天：跨设备保持同一星海气候和候选材质。
- 第二天：自然变化。
- 体验版本升级：允许统一迁移，但已保存星笺必须使用保存时的版本回放。

### 10.2 七种星海气候

| 气候 | 主色与质感 | 动态特征 |
| --- | --- | --- |
| 玫瑰气辉 | 亮玫瑰粉、珠光白、少量烟紫 | 远处薄光缓慢扩散 |
| 蓝银潮汐 | 雾蓝、银白、淡紫 | 星尘像潮汐横向流动 |
| 金雾星尘 | 暖金、莓粉、深梅色 | 极细金粉在近景闪现 |
| 玻璃极光 | 冰粉、蓝紫、透明玻璃 | 低亮光带缓慢折射 |
| 无月深空 | 墨紫、珠光白、少量粉光 | 星点稀疏，边缘更清楚 |
| 粉紫流星雨 | 明亮粉、淡紫、银色 | 少量短流星，不持续轰炸 |
| 晨雾星海 | 珍珠粉、灰紫、微暖白 | 雾层变亮，像夜晚将尽 |

任何气候都不能让整屏只剩暗紫，也不使用大面积绿色。粉色和珠光白承担主要亮点，紫色负责空间深度。

### 10.3 三层变化

每天的变化由三层组合完成：

1. 星海气候：控制背景、雾和远景运动。
2. 星星材质：毛玻璃、珠光、晶体、冰霜、光环、细砂等。
3. 当日天象：双星掠过、轻流星、环带、微弱极光等；一晚最多一种。

同一天的变化保持稳定，不以频繁刷新制造新鲜感。

### 10.4 与真实记录联动

只使用不冒犯隐私、不会改变结果的轻联动：

- 当天有语音记录：旅途中出现一圈声纹涟漪。
- 当天记录较多：光点尾迹略丰富，但不表示优劣。
- 当天没有记录：星海更安静，并允许无字星。
- 关系记录、星座与照片联动留待后续版本，不在本轮实现。

## 11. 内容生成规则

### 11.1 有当天记录

- 优先摘取用户原话中的完整短句，不把原意改成模板化鸡汤。
- 状态词采用推测语气，界面文案使用“从今天的记录里，我拾到……”而不是“你的心情是……”。
- 当前 AI 未接通时，使用可靠的本地提取规则也可以完成基础星笺，并明确不显示“AI 已总结”。
- 如果无法可靠判断情绪，状态词留空或使用“此刻”，不能强行显示“平静”。

### 11.2 没有当天记录

不得使用固定句“把一点微光，留给明天的自己”冒充用户当天的表达。只提供：

- 留一颗无字星。
- 说一句再留下。
- 返回记录。

### 11.3 内容长度

- 状态词：最多 12 个汉字。
- 一句回响：建议 32 个汉字，硬上限沿用现有 100 字保存能力。
- 超过卡面容量时只显示摘要，完整原文保留在来源记录中。

## 12. 状态与保存逻辑

### 12.1 前端状态机

主线实现必须显式处理以下状态，不能依靠多个布尔值偶然组合：

`idle → invited → journey → star-sea → picking → revealing → syncing → saved`

分支状态：

- `revisit`：今天已有云端星笺。
- `pending-sync`：本地已形成星笺，云端尚未确认。
- `save-error`：保存失败，内容保留。
- `no-content`：今天无记录。
- `reduced-motion`：跳过镜头运动但保持完整逻辑。

### 12.2 初次保存

- 用户完成摘取手势后立即形成本地星笺，并发起云端保存。
- 保存请求必须防重复；同一账号、同一北京时间日期只创建一条。
- 云端返回有效记录后才能增加累计数量并显示“已留在今天”。
- 网络结果未知时不增加累计数量，显示“已留在本机 · 等待同步”。

### 12.3 修改保存

现有接口保留首次内容、不允许更新，不足以支持“调整星笺”。本次需要增加当天记录的受控更新能力：

- 仅允许当前账号更新当天自己的状态词和回响。
- 更新不新增日期、不增加累计天数。
- 使用版本号或更新时间避免两台设备互相静默覆盖。
- 冲突时保留双方内容，并让用户选择，不自动丢弃较新的手动文字。

### 12.4 撤销

- 摘星后 5 秒内可以撤销。
- 尚未发出请求时直接取消。
- 已创建成功时执行真实删除或撤销操作，并以服务器确认结果为准。
- 如果首版无法安全支持服务端撤销，则不显示虚假的“放回星海”；必须在实现前二选一。

### 12.5 跨午夜

- 所有日期以 `Asia/Shanghai` 为准。
- 旅途中跨过午夜，提交时必须重新确认服务器日期。
- 用户文字和已选材质保留，提示“已经是新的一天，是否把这颗星留给今天”。

## 13. 数据需求

现有每日记录只有日期、状态词、回响和创建时间，无法跨设备还原选中的星。建议为每日星笺增加以下字段：

| 字段 | 用途 |
| --- | --- |
| `star_variant` | 三颗候选星中实际选择的编号 |
| `theme_id` | 当日星海气候 |
| `material_id` | 星笺材质 |
| `visual_seed` | 稳定还原星尘、光环和细节 |
| `experience_version` | 保证未来升级后可回放旧星笺 |
| `source_note_ids` | 记录这句话来自哪些当天记录 |
| `updated_at` / `revision` | 支持安全编辑和跨设备冲突判断 |

要求：

- 新字段需要真实云端迁移；不能只存浏览器本地。
- 老记录没有这些字段时使用日期稳定生成兼容外观。
- 预览数据必须标记为演示，不写入正式表。
- 私人记录和来源 ID 继续受账号权限保护。

## 14. 性能设计

### 14.1 必须移除的并发负担

主流程不再同时运行以下组合：

- 星幕动画。
- 高分辨率正反面 Canvas 图片生成。
- `card.glb` 模型加载。
- Rapier 物理和绳带模拟。
- 第二套三维场景。

原 `LanyardCheckin`、矩形卡面纹理生成与星笺主流程解除。保留相关文件只用于历史回退也不得在新流程中加载。

### 14.2 推荐渲染结构

- 整段旅程最多一个画布或一个 WebGL 上下文。
- 星笺本体优先使用 SVG 轮廓 + DOM 文字；同一星的视觉变量贯穿候选与展开状态。
- 背景星尘可用 Canvas 或 WebGL，文字和按钮不能放进画布。
- 每一时刻最多一个 `requestAnimationFrame` 循环。
- 星体位置、尺寸和锚点在进入阶段或窗口变化时计算，不在每帧重复读取布局。
- 不可见、页面隐藏、弹层关闭后立即停止动画循环。

### 14.3 自适应质量

至少提供三档：

- 高：完整星尘、一次天象、细微折射。
- 中：降低粒子量，移除部分折射和景深。
- 低：静态星海 + CSS/SVG 星笺，只保留必要过渡。

自动降级不能改变可操作性、内容或保存能力。

### 14.4 性能验收指标

- 点击入口后 250ms 内必须出现可见响应。
- 从摘下星到星笺文字可读，目标不超过 700ms。
- 桌面端主流设备动画目标 55fps 以上；不得长期低于 45fps。
- 移动端目标 50fps 以上；低性能模式不得长期低于 30fps。
- 动画期间不得出现超过 100ms 的主线程长任务。
- 关闭弹层后不保留持续动画、物理计算或隐藏的三维上下文。

## 15. 易用性与无障碍

- 支持鼠标、触控、键盘三种完整路径。
- 候选星使用真实按钮语义，名称为“摘下第 X 颗星：材质名”。
- Enter/空格选择；左右方向键切换候选；Esc 退出。
- 焦点进入弹层后保持在弹层内，关闭后返回触发入口。
- 减少动态效果模式直接展示星海和淡入星笺，不播放穿越、视差或持续摇摆。
- 星笺正文与背景达到可读对比；粉紫发光不能作为唯一状态提示。
- 保存状态使用文字与图标共同表达，并通过克制的 `aria-live` 播报一次。
- 所有手机触摸目标至少 44px，候选星建议至少 48px。

## 16. 隐私与真实状态

- 星河掠过旧记录时默认不显示完整句子。
- 提供“共享屏幕模式”：隐藏旧关键词、当天原话和关系内容，只保留抽象星光。
- AI 未调用时不能显示“AI 已生成”或类似成功文案。
- 演示预览不得写入云端、增加天数或显示真实保存成功。
- 网络失败、账号失效、数据库未初始化时必须保留用户文字并说明真实状态。

## 17. 文案基线

### 邀请

- 今晚的星海，已经亮起。
- 今天留下的念头，正在远处发光。

### 旅程

- 跟着这一点光，往前走。
- 有些念头没有消失，只是去了更远的地方。

### 星海

- 今晚的星，在这里。
- 轻触，或把它带向自己。

### 展开

- 这一颗，留给今天。
- 从今天的记录里，我拾到……

### 保存

- 已留在今天。
- 已留在本机 · 等待同步。
- 还没有同步成功，这颗星和你的文字仍在。

避免使用：

- “恭喜完成打卡”。
- “连续打卡中断”。
- “抽到稀有星星”。
- “AI 判断你的情绪是”。
- 任何未被服务器确认的“保存成功”。

## 18. 边界场景

主线必须逐项处理：

1. 今天没有任何记录。
2. 今天已经摘过星。
3. 旅途中刷新页面。
4. 选择后立即关闭。
5. 选择后断网。
6. 保存请求返回超时但服务器可能已经写入。
7. 两台设备同时摘星。
8. 两台设备同时修改星笺。
9. 旅途中跨过北京时间午夜。
10. 浏览器切到后台再返回。
11. WebGL 不可用或上下文丢失。
12. 用户开启减少动态效果。
13. 手机横竖屏切换。
14. 很长的中文句子、英文长词和 emoji。
15. 旧账号已有矩形吊牌记录但没有新视觉字段。

## 19. 测试与验收

### 19.1 核心流程

- 保存当天第一条记录后，邀请只出现一次且不遮挡继续输入。
- 第一次进入可以完成“穿越 → 星海 → 摘星 → 展开”。
- 被选中的星与展开后的星笺颜色、材质和光环一致。
- 摘星后不再出现第二个“收下今天的星”必点按钮。
- 当天再次进入直接回看，不重复摘星。
- 没有当天记录时不会出现伪造金句。

### 19.2 保存与同步

- 云端确认前累计数量不增加。
- 重复点击、重复触摸和双设备并发不会创建两条同日记录。
- 网络失败时星笺和用户文字不丢失。
- 修改星笺只更新内容，不增加天数。
- 预览模式全程不调用正式保存接口。

### 19.3 视觉与布局

检查视口：`1440×900`、`1280×720`、`390×844`、`360×800`。

- 七芒星轮廓清楚，中央文字不被星芒切掉。
- 文案 32 个汉字时不溢出，100 字时能安全截断并查看全文。
- 候选星、引导、关闭和保存状态互不遮挡。
- 不出现横向滚动、白边、模糊纹理字或整屏暗紫。
- 同一天刷新后视觉稳定，第二天才变化。

### 19.4 操作与性能

- 鼠标滚轮、触控板、点击、拖动、键盘都能完成。
- 滚轮不会一次越过全部阶段，也不会在抵达后继续锁住页面。
- 快速跳过、Esc 退出、减少动态效果均有效。
- 页面隐藏与弹层关闭后动画停止。
- 使用实体手机至少验证一台 iPhone 尺寸和一台常见 Android 尺寸；桌面模拟不能替代实体触摸验收。

### 19.5 自动化与人工检查

- 为状态机、同日幂等、重复进入、保存失败、跨午夜、编辑冲突和减少动态效果增加行为测试。
- 浏览器端记录进入响应时间、摘星到文字可读时间、长任务和动画帧率。
- 对桌面和手机各保存关键阶段截图：邀请、穿越、三颗星、正面、背面、同步失败。
- 完成真实私人账号的电脑创建、手机读取和手机修改后电脑回看的跨设备流程。

## 20. 实施顺序

### 阶段 1：先修逻辑与状态

1. 把今日星入口迁移到记录页，设置页改为回看入口。
2. 建立明确的摘星状态机和“当天已有记录直接回看”逻辑。
3. 使用稳定日期种子替代每次打开随机主题。
4. 保留现有接口的真实读取和幂等创建行为。

### 阶段 2：完成同一颗星

1. 制作三颗候选星。
2. 实现候选星到七芒星笺的连续展开。
3. 使用 DOM/SVG 清晰文字层替换纹理文字。
4. 从主路径移除矩形 Lanyard、GLB、卡面 Canvas 和第二套三维加载。

### 阶段 3：加入桌面旅程与移动端短路径

1. 完成三阶段滚轮推进和快速跳过。
2. 加入移动端 1.2 至 1.8 秒短推镜。
3. 完成减少动态效果和低性能降级。
4. 加入七种每日气候和稳定回放。

### 阶段 4：保存升级与跨设备

1. 增加星笺视觉字段、来源字段和版本字段。
2. 支持当天内容的安全修改。
3. 处理同步中、未知结果、冲突和跨午夜。
4. 完成真实账号跨设备验收。

### 阶段 5：体验和性能验收

1. 按真实用户路径连续使用至少两天，检查重复体验是否疲劳。
2. 在桌面触控板、鼠标滚轮和手机触摸上分别检查。
3. 记录性能指标并按设备自动降级。
4. 修复全部遮挡、误触、等待无反馈和保存状态不真实的问题后再宣布完成。

## 21. 完成定义

只有同时满足以下条件，摘星重构才算完成：

- 用户能清楚感受到“我的一句话变成光，我穿过星河，摘下它，它展开成今天的星笺”。
- 视觉上始终是同一颗星，没有矩形吊牌替换。
- 首次体验有沉浸感，同日重复进入足够快。
- 桌面端一镜到底可滚动推进、可跳过、不会劫持后续页面滚动。
- 手机端不用滚轮、不依赖悬停，也能单手完成。
- 星笺文字清晰，卡面不遮挡说明或按钮。
- 摘星即完成，无第二次必点确认。
- 同一天跨设备显示同一张星笺；修改和保存状态真实。
- 无记录、断网、账号失效、跨午夜和低性能设备都有可用降级。
- 相关自动测试、浏览器实测、实体手机实测和真实跨设备流程全部通过。
