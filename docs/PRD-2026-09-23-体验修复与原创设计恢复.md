# 拾念体验修复与原创设计恢复 PRD

版本：2026-09-23  
状态：执行中  
目标：恢复用户原有的创意方向，修复影响真实使用的交互与排版问题，并统一移动端和桌面端的视觉品质。

## 1. 产品原则

1. 保留“拾念、星河、微光、摘星、吊牌、回响”这套原创意象，不用通用后台界面覆盖它。
2. 所有表单都应像产品的一部分，而不是浏览器默认控件；视觉以低饱和粉、烟紫、珠光白、雾蓝的透明玻璃为主。
3. 动效服务于记录和回看：有响应、有层次，但不能遮字、抢操作或拖慢手机。
4. 同一种内容只保留一个主要展示入口，避免闪卡、打卡和备份功能重复堆叠。
5. 自动生成必须允许用户修改；保存成功、AI 成功和演示状态必须真实区分。

## 2. 录入首页

### 现存问题

- “此刻，想记下什么？”下方只有背景上部响应，输入区域和下方空间缺少连续互动。
- 当前排版削弱了原有星河与语音波形的中心体验。

### 目标方案

- 保留“拾念 / 此刻，想记下什么？”及星河动态背景。
- 输入卡改为贯穿标题下方的半透明“回声玻璃台”，聚焦、输入、语音状态都会产生柔和光晕和波纹响应。
- 输入框下方保留明确的语音入口、草稿状态、来源入口和保存动作；空白区域增加轻量呼吸光带，不做无意义装饰。
- 聚焦输入时降低背景运动，但不让下方完全静止。

### 验收标准

- 标题、输入框、语音按钮、保存按钮形成一条清晰操作路径。
- 桌面端与手机端输入区域无大块失去层次的空白。
- 输入、聚焦、录音三种状态有可见反馈，文字始终清晰。

## 3. 来源选择与来源表单

### 现存问题

- 来源类型使用普通下拉框，廉价且与整体风格不一致。
- 来源链接、类型和补充信息缺少层级。

### 目标方案

- 把“播客、文章、书籍、视频、生活、其他”改为玻璃质感的图标分段选择器。
- 选择某种来源后，表单的提示词与图标同步变化。
- 链接与名称作为主要字段，时间点和原文片段放在渐进展开区。
- 来源区域使用雾面玻璃、细边缘高光和低饱和粉蓝色，不使用默认白底控件。

### 验收标准

- 无浏览器默认下拉框。
- 手机端类型选项可横向滑动或自然换行，不拥挤、不误触。
- 收起来源后仍能看见已选择的来源类型和“已有来源”状态。

## 4. 语音重复识别修复

### 根因

当前实现先把最终识别文本追加进累计文本，又把同一次事件包含的完整 transcript 当作临时文本再次追加，因此浏览器同时返回 interim 与 final 结果时会出现重复。

### 目标方案

- 每次语音会话固定一份输入前文本。
- 每次 `onresult` 都从本次结果列表重新组合“最终片段”和“临时片段”，不增量重复拼接同一个片段。
- 停止、报错、组件卸载时清理识别实例；快速重复点击不能创建两个识别会话。

### 验收标准

- 一句话从临时结果转成最终结果后只出现一次。
- 连续说两句话保持正确顺序。
- 停止后原文字不丢失，重新开始不会带入上一轮临时结果。

## 5. 灵感集与闪卡橱窗

### 现存问题

- “念头星图”命名不符合用户偏好。
- 橱窗卡片过大并遮挡说明文字。
- 橱窗下方重复渲染一套大闪卡；油画未完整覆盖卡面并出现空白边。

### 目标方案

- 页面标题恢复为“灵感集”，导航恢复为“灵感集”的清晰表达。
- 闪卡收藏只保留一个橱窗；删除橱窗下方重复的大卡列表。
- 橱窗卡片缩小，说明文字与卡片分区，不相互遮挡。
- 油画使用完整覆盖策略并保留安全裁切位置，不出现白边。
- “记一条灵感”改为更轻、更贴近标题区的玻璃动作按钮。

### 验收标准

- 任何常见手机宽度下，标题、说明、数量、闪卡互不覆盖。
- 同一张闪卡在页面中只出现一次主要展示。
- 图片铺满卡面，无白边、拉伸或露底。

## 6. 待办票根

### 现存问题

- 手机端票根变成狭长竖卡，丢失票根意象。
- 所有票根偏紫，缺少内容区分。

### 目标方案

- 手机端保持横向票根比例；列表采用横向可滑动轨道或全宽横票。
- 按内容稳定分配雾粉、月蓝、银灰、青绿、暖金等低饱和材质。
- 保留撕线、编号和状态，但压缩非必要文字。

### 验收标准

- 360px 宽手机上票根仍明显是横向票根。
- 连续票根不会全部使用同一紫色。
- 操作按钮可触达且不覆盖票面文字。

## 7. 摘星与每日吊牌

### 现存问题

- 当前牌面文字模糊、材质发脏，牌体遮挡引导文字。
- 先选星、再选心情、再写金句、再点打卡，步骤过多。
- 摘星后的结果与当天记录没有联系。

### 目标方案

- 星空帘幕与“摘一颗星”的仪式感保留。
- 打开后先根据当天已有灵感、听后感和个人表达自动生成“今日心情 + 一句回响”；无今日记录时给出诚实的轻量默认文案。
- 用户摘下一颗星后直接生成高分辨率吊牌；默认一步完成，编辑心情和文字放入“调整这张牌”。
- 吊牌保持圆角实体牌形，不改成星形；使用清晰 DOM 文字层或高分辨率纹理，避免 WebGL 小字模糊。
- 牌体与说明区分层布局，拖拽时也不能遮住关键按钮和状态。
- 当天已生成后，设置页直接显示今日牌和打卡天数，不要求再次走完整流程。

### 验收标准

- 摘星主流程最多两步：进入摘星、选择一颗星。
- 自动文案明确来自“今日记录”，且保存前可修改。
- 牌面文字在桌面和手机上均清晰；卡片不遮挡引导、错误或保存状态。

## 8. 账号、备份与设置

### 现存问题

- “返回正式入口”和设置页使用偏绿样式，与整体粉紫星河不一致。
- 三个备份动作等权堆叠，显得复杂。

### 目标方案

- 正式入口按钮改为偏粉的半透明异形玻璃按钮，取消绿色。
- 账号与设置统一使用雾粉、珠光白、烟紫、少量雾蓝。
- 备份区以“导出备份”为主操作；“恢复备份”和“导出阅读版”收进次级菜单或折叠区。
- 每个动作使用结果导向的短文案，并清楚标记预览不可用状态。

### 验收标准

- 设置页不存在突兀的绿色主按钮或大白底块。
- 默认首屏只突出一个备份主操作。
- 预览模式不会假装已保存或已同步。

## 9. 质量检查范围

- 桌面：1440×900、1280×720。
- 手机：390×844、360×800。
- 检查中文长句、空数据、3 条以上闪卡、3 条以上票根、语音 interim/final 切换、重复点击、降低动态效果。
- 运行类型检查、生产构建和与本次行为相关的测试。
